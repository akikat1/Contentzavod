# Железо: бюджет по стадиям

Целевая машина: **i5-11400F (6C/12T) · 16 ГБ DDR4 · GTX 1650 4 ГБ · SSD 1 ТБ**.
Критерий «работает»: пик VRAM < 3.6 ГБ и RSS < 12 ГБ за весь прогон — оба пика пишутся в
`workspace/jobs/<job>/manifest.json` (`resources`).

## Что где считается

| Стадия | Ресурс | Пик памяти | Заметки |
|---|---|---|---|
| research, beatsheet, script, metadata, judge | сеть (пул ключей) | < 200 МБ | локальная LLM нужного класса в 4 ГБ не помещается |
| voice (edge-tts) | сеть + CPU | < 200 МБ | кэш синтеза: повторный прогон бесплатен |
| humanize | CPU | ~0.5 ГБ на 10 мин | свёртка с комнатой блоками — память не растёт с длиной |
| RVC (опц.) | **GPU** ~3 ГБ | | чанки по 30 с |
| align (faster-whisper, опц.) | **GPU** ~1 ГБ | | `small` + `int8`; `large-v3` вместе с выравниванием не влезает |
| assets: MiDaS (опц.) | **GPU** ~0.5 ГБ | | без torch — эвристическая глубина |
| assets: ComfyUI SDXL-Turbo (опц.) | **GPU** ~3.5 ГБ | | `--lowvram`; основной путь — Nano Banana в облаке |
| sound | CPU | ~1 ГБ на 10 мин | микширование в numpy, без filter_complex |
| render | CPU + NVENC | ≤ 2 ffmpeg одновременно | посценно + concat без перекодирования |

GPU-стадии никогда не работают одновременно: межпроцессный мьютекс `data/gpu.lock` + явная выгрузка модели.

## NVENC на GTX 1650
Первая ревизия (TU117) несёт энкодер поколения Volta: **H.264 есть**, B-кадров в HEVC нет. Завод использует
только `h264_nvenc` и проверяет его тестовым кадром при старте (`factory doctor`); если драйвер не отдаёт
энкодер — `libx264 -preset veryfast`. Параметры кодирования одинаковы для всех сцен — иначе склейка
без перекодирования ломается.

## Ожидаемое время одного ролика (7 минут, 1080p)
Оценка по плану — измерьте на своей машине: `manifest.json` → `stages.*.seconds`.

| Стадия | Время |
|---|---|
| исследование + драматургия + сценарий (пул) | 5–9 мин |
| синтез речи (2–4 голоса) + гуманизация | 3–5 мин |
| изображения (Nano Banana, 60–80 шт.) + сток | 5–10 мин |
| параллакс + рендер сцен + склейка | 8–15 мин |
| звук | 1–2 мин |
| 4 шортса | 4–6 мин |
| публикация | 5–15 мин |
| **итого** | **~40–70 мин → 2–3 ролика в сутки** |

Замер в облачной песочнице разработки (4 vCPU, без GPU, офлайн-режим, 640×360): 80-секундный ролик со всеми
16 стадиями и двумя шортсами — ~60 с. Время рендера растёт примерно линейно с числом пикселей и длиной.

## Диск
Джоб занимает 3–5 ГБ промежуточных файлов. После публикации демон оставляет финалы и манифесты
(`schedule.cleanup_after_publish`), история — `schedule.keep_jobs` джобов. Производство останавливается с
алертом, если свободно меньше `schedule.min_free_disk_gb` (40 ГБ). Кэш синтеза и изображений
(`assets/cache/`) можно чистить вручную.

## Что менять при апгрейде

| Апгрейд | Что включить |
|---|---|
| 8+ ГБ VRAM | `align.whisper_model: large-v3`; ComfyUI с FLUX-schnell GGUF как второй провайдер изображений |
| 12+ ГБ VRAM | Wan 2.2 5B (Apache 2.0) для коротких `[MOTION]`-вставок — нужен новый провайдер `video/` |
| 24 ГБ VRAM | локальная LLM (Qwen3-27B и аналоги) как основной мозг, облако — фолбэк |
| 32 ГБ ОЗУ | `render.parallel_scenes: 4` |
| быстрый CPU | `render.quality: high` (x264 medium) при отсутствии NVENC |
